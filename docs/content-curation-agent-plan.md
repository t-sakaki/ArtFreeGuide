# アートニュース連動・コンテンツ拡充エージェント構想

美術館の企画展・テレビ番組・世間の話題を起点に、AIエージェントが関連作品を探索してツアー案や辞書・キャッシュ下準備を行う仕組みの設計メモ。
この文書は実装前の合意・段階的検証用であり、まずはアプリ改修なしで試せる構成から始める。

## 1. 目的と狙い

- **コンテンツの自然な拡張**: 話題の展覧会や放送直後のテレビ番組に合わせて、「いま観たい・知りたい」作品群をタイムリーに追加する。
- **初回待ち時間（約60秒）の解消**: 話題化によってアクセスが集中する前に、画像解決と主要言語（`ja`, `en` 等）の解説生成を `/api/chat` 経由で事前ウォームアップしておく。
- **回遊性の向上**: 単発の作品追加ではなく `src/lib/playlists.ts` の「ツアー（3〜5作品）」としてまとめることで、1作品から次の一枚へ自然に案内する。
- **表記揺れ・多言語辞書の強化**: メディアや展覧会でよく使われる慣用タイトル・略称を `title_aliases` や `names.data.json` に取り込み、検索・音声入力のヒット率を上げる。

## 2. 設計上の原則（ArtFreeGuide 固有の制約）

1. **時事情報を作品解説そのものに混ぜない**
   - `/api/chat` が生成し D1（`artwork_guides`）に保存する解説は永続キャッシュされる。ここに「〇〇年〇月の〇〇展で展示中」等の時間依存情報を入れると陳腐化する。
   - **「いま話題の理由」はツアー側の `subtitle` や各作品の `cue` に持たせ**、作品解説自体は普遍的に保つ。
2. **D1 への解説直接書き込み禁止・作品名は日本語が正**
   - 解説の事前生成は必ず `/api/chat` エンドポイントを叩いて保存する（D1 への直接 `INSERT` 禁止）。
   - コード・辞書内の正表記は日本語とし、多言語表記・別名は `src/lib/names.ts`（`names.data.json` / Supabase 連携）を経由する。
3. **全自動公開ではなく承認制（Human-in-the-loop）**
   - 同名異作の取り違え、表記揺れによる重複、実在しない作品の混入を防ぐため、エージェントは「調査〜下書き作成」までを担当し、公開・マージは人間が確認して行う。
4. **画像解決（パブリックドメイン）への配慮**
   - 著作権保護下の近現代作品は Wikimedia Commons に画像がなく 🖼️ プレースホルダとなる。
   - 企画展が現代美術中心の場合は、「その展覧会を理解するためのルーツとなった古典・印象派・浮世絵ツアー」として構成するなど、画像が取れる名画を軸に組む。
5. **Embedding の整合性維持**
   - 新規作品をカタログへ追加した場合は、`embedding_nv`（`match_artworks_nv` 用）が欠けないよう補完を回す。

## 3. エージェントのパイプライン（3ステップ）

| ステップ | 役割 | やること |
|---|---|---|
| **1. Scout（情報収集）** | 話題の検知 | 美術館の新着展覧会、美術メディア、TV番組（美術特集）、SNS・検索トレンドを収集し、テーマ候補を3〜5件抽出する。 |
| **2. Curator（探索・編成）** | 作品選定と突合 | 各テーマに沿って3〜5作品のミニツアー案を作成。既存カタログ（Supabase）と照合し、新規作品・別名（`title_aliases`）・5言語名（ja/en/fr/zh/es）・画像取得可否（Commons/Wikidata）を確認する。 |
| **3. Preparer（下準備）** | 登録とウォーム | 人間の承認後、辞書更新（`scripts/sync_names.mjs`）・画像解決（`/api/artwork-image`）・事前解説生成（`scripts/warm_cache.mjs`）・ベクトル補完（`scripts/backfill_embeddings.mjs`）を実行する。 |

## 4. 段階的な導入ロードマップ

### Phase 1: アプリ改修ゼロで効果検証（現在地〜）
- **進め方**: エージェント（手元実行または定期実行）にニュース調査〜ツアー下書きレポートを作成させ、人間が確認したものを `feat/` ブランチの PR として `src/lib/playlists.ts` / `names.data.json` に取り込む。
- **既存の仕組みの活用**:
  - 辞書同期: `node scripts/sync_names.mjs`
  - 事前ウォーム: `node scripts/warm_cache.mjs --locales=ja,en --titles=...`
  - Embedding 補完: `node scripts/backfill_embeddings.mjs`
- **検証すること**: どの切り口（大型展覧会 / TV番組 / 季節テーマ等）が閲覧・再生に繋がりやすいか、画像解決できない作品がどれくらい混ざるか。

### Phase 2: 下書き生成の半自動化
- **進め方**: 週次などで Scout + Curator を自動実行し、GitHub Issue または Draft PR として「今週のツアー候補」を提案させる。
- 画像解決チェック（`/api/artwork-image` または Wikidata/Commons 疎通）までスクリプト化し、人間が「画像あり/なし」「表記妥当性」を一目で判断できる形にする。
- **実装スクリプト**: `scripts/scout_art_topics.mjs`
  ```bash
  # 美術館・美術メディアを巡回し、候補作品の辞書突合・画像可否を Markdown 出力
  node scripts/scout_art_topics.mjs \
    --url=https://www.nmwa.go.jp/jp/exhibitions/2026turner.html \
    --candidates="戦艦テメレール/J.M.W. ターナー,雨、蒸気、速度――グレート・ウェスタン鉄道/J.M.W. ターナー"
  ```
- **週次自動実行**: `.github/workflows/weekly-art-scout.yml`（毎週月曜 09:00 JST および手動実行）により、`scripts/scout_art_topics.mjs --follow-links=2` の結果を GitHub Issue として自動提案する。

### Phase 3: 再デプロイ不要の動的特集ツアー（手応えが出たら検討）
- 現在は `src/lib/playlists.ts` と `names.data.json` がビルド時確定のため、ツアー追加のたびにデプロイが必要。
- 頻繁に時事特集を入れ替えたくなった場合、D1 に特集ツアー用テーブル（例: `featured_tours`、`status = draft | published`）を設け、管理画面（`/admin/*`）または `scripts/mcp_admin_server.mjs` 経由で下書き登録 → 人間が承認すると即時公開＆ウォームされる仕組みへ拡張する。

## 5. エージェントに出力させる下書きフォーマット（Phase 1 用）

Phase 1 でエージェントが提案する際は、最低限以下を揃える。

1. **話題の出典と理由**（展覧会名・会期・番組名・URL）
2. **ツアー案**（`id`, 5言語の `title` / `subtitle`, 3〜5作品の `title` / `artist` / 5言語 `cue`）
3. **カタログ突合結果**
   - 既存カタログに一致したもの（表記揺れがあれば `title_aliases` 候補）
   - 新規追加が必要な作品・作家（5言語表記案＋パブリックドメイン画像有無の見込み）
4. **事前ウォーム対象コマンド例**（マージ・デプロイ後にそのまま流せる形）
