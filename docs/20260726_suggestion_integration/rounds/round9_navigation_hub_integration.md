# 履歴・作品・プレイリスト UI 統合 (Round 9) 実装計画書

## 1. 概要
### 目的
現在、「履歴選択」「作品変更（検索）」「プレイリスト選択」の3つの機能が個別のUI/ロジックとして分散しており、ユーザー体験が断片化している。これらを単一の**「ナビゲーション・ハブ (Navigation Hub)」**に統合し、ユーザーが「作品を切り替える」という目的を一つのインターフェースで完結できるようにする。

### ユーザー体験の変化
- **Before**: 履歴を見たいときは履歴ボタンを、別の作品を探したいときは入力欄を、ツアーを選びたいときはプレイリストメニューを、それぞれ個別に操作していた。
- **After**: 「ナビゲーション・ハブ」を開くだけで、「最近見た作品」「全作品から検索」「保存済みツアー」の3つをタブで切り替えて選択でき、迷わずスムーズにガイドを開始できる。

---

## 2. UI/UX 設計

### 共通コンポーネント
- **コンポーネント名**: `NavigationHub` (または `GuideNavigationHub`)
- **形式**: 下からせり上がるドロワー (Drawer) 形式。既存の `HistoryPlaylistDrawer` をベースに拡張する。

### タブ構造
上部にタブ切り替えを配置し、コンテンツエリアを切り替える。

| タブ名 | アイコン | 期待される挙動 |
| :--- | :---: | :--- |
| **作品検索** | 🔍 | 検索窓を配置。入力に応じて作品候補を提示し、選択すると即座にその作品のガイドを開始する。 |
| **プレイリスト** | 🏛️ | 保存済みのツアー一覧を表示（横スクロール）。選択するとツアーの1曲目から開始し、ツアーモードへ移行する。 |
| **履歴** | 📜 | 最近閲覧した作品をリスト表示。選択するとその作品のガイドを再開する。 |

### 遷移フロー
1. **選択**: ユーザーがいずれかのタブで作品/プレイリストを選択。
2. **State更新**:
   - 単一作品の場合 $\rightarrow$ `setArtwork`, `setArtist` 等の基本Stateを更新し、APIからガイドデータを再取得。
   - プレイリストの場合 $\rightarrow$ `setPlaylist` を更新し、ツアーモードを有効化。
3. **完了**: `NavigationHub` を閉じ、メイン画面に選択した作品の解説を表示してガイドを開始する。

## 3. 技術的アプローチ

### 影響を受けるファイル
- `src/app/ArtFreeGuideClient.tsx`: メインのState管理、ハブの表示制御、作品切り替えロジックの集約。
- `src/components/HistoryPlaylistDrawer.tsx`: `NavigationHub` へ統合・リファクタリングして削除。
- `src/components/NavigationHub.tsx` (新設): 統合されたUIコンポーネント。

### 削除・統合される要素
- **コンポーネント**: `HistoryPlaylistDrawer` $\rightarrow$ `NavigationHub` へ統合。
- **関数**: 
  - 各所で分散していた `onSelectHistory`, `onSelectPlaylist` 等のハンドラを `handleArtworkSelect` などの共通関数に集約。

### 新設される State / 関数
- **State**:
  - `showNavigationHub`: ハブの開閉状態 (boolean)。
  - `activeNavTab`: 現在選択中のタブ (`'search' | 'playlist' | 'history'`)。
- **関数**:
  - `handleArtworkSelect(artworkData: ArtworkData)`: 作品情報を元にガイドを切り替える共通関数。
  - `handlePlaylistSelect(playlistSlug: string)`: プレイリストをロードし、ツアーを開始する関数。

## 4. 段階的実装ステップ

### Step 1: NavigationHub の骨格作成とタブ実装
- 既存の `HistoryPlaylistDrawer` を `NavigationHub` にリネームし、上部にタブ切り替え UI を実装する。
- タブによるコンテンツの表示/非表示切り替えができる状態にする。
- **DoD**: タブを切り替えて「検索」「プレイリスト」「履歴」の各エリアが表示されること。

### Step 2: 「作品検索」タブの統合
- 現在 `ArtFreeGuideClient.tsx` 内にある検索入力ロジック（および `ArtworkSuggestion`）を `NavigationHub` 内に移植する。
- 検索結果から作品を選択した際に、メイン画面の作品が切り替わるように接続する。
- **DoD**: ハブ内の検索窓から作品を選択し、ガイドが切り替わること。

### Step 3: 「履歴」および「プレイリスト」タブの移行
- 既存の履歴表示・選択ロジックと、プレイリスト取得・選択ロジックを `NavigationHub` の各タブに完全に移行する。
- `ArtFreeGuideClient.tsx` から不要になった古い Drawer 呼び出しを削除する。
- **DoD**: 履歴からの再開およびプレイリストからのツアー開始が、ハブ経由で正常に動作すること。

### Step 4: UX ブラッシュアップとクリーンアップ
- アニメーションの調整、空状態（履歴なし等）の表示改善。
- 重複していた State や関数を整理し、コードをクリーンにする。
- **DoD**: 全体の動作がスムーズであり、不要なコードが削除されていること。

## 5. 検証プラン

| テストケース | 期待される結果 |
| :--- | :--- |
| **検索からの遷移** | ハブの「作品検索」で作品を選択 $\rightarrow$ ハブが閉じ $\rightarrow$ その作品の解説が表示されること。 |
| **履歴からの遷移** | ハブの「履歴」から過去の作品を選択 $\rightarrow$ ハブが閉じ $\rightarrow$ 当該作品の解説が表示されること。 |
| **ツアーの開始** | ハブの「プレイリスト」からツアーを選択 $\rightarrow$ ハブが閉じ $\rightarrow$ ツアーの最初の作品から開始されること。 |
| **タブ切り替え** | 検索 $\leftrightarrow$ プレイリスト $\leftrightarrow$ 履歴 の切り替えが瞬時に行われ、各状態が保持されていること。 |

---

## 6. リスクと対策

- **リスク**: 検索ロジックの移行により、既存のオートコンプリートや検索体験が損なわれる。
- **対策**: `ArtFreeGuideClient.tsx` で動作していたロジックをそのまま移植し、UI 構造のみを変更することで機能的な退行を防ぐ。
- **リスク**: プレイリストのロード中にハブを閉じた場合の挙動。
- **対策**: ロード状態 (loading) を適切に管理し、選択確定までハブを閉じない、あるいは非同期処理の完了後に適切に State を更新する。
